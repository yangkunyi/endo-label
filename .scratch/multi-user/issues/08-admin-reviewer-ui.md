# 08 管理员/审阅/标注员三侧界面范围

Type: grilling
Status: resolved
Blocked by: 03, 04

## Question

基于工单 03、04 的模型结论，定三侧 UI 范围：

- 管理员：用户管理、分配看板（按 (Clip, Task type) 行展示：谁手上有什么、进度一眼可见）、自动分配入口、已交付标记入口（取用留痕）。哪些做成独立页面，哪些并入现有界面。
- 标注员：现有单机工作台保留多少，加什么（我的任务列表、提交/撤回；被打回时看到备注）。
- 审阅者：怎么看、怎么改、在哪个界面改（复用现有标注台直接改？）。
- 明确第一版砍掉的界面项，写进 spec 的非目标。

## Answer（2026-09-08）

选定 **B：按优雅架构重建前端组织；ClipDesk 拆解随实现渐进做**（用户原话：边做边重构优于最后清历史包袱）。

- **路由化**：`/login`、`/desk/:clipId/:kind`（URL 携带条目身份，可刷新可深链，审阅者可直接甩链接）、`/admin/users`、`/admin/assignments`、`/admin/projects`、`/admin/vocab`。两层布局：登录壳 + 应用壳（顶栏：当前身份、登出、我的任务、管理入口）。
- **角色即能力**：全系统一个工作台组件，不写角色分支副本；按钮渲染由服务器下发的**能力载荷**（`/me` + 条目 capabilities）决定——与工单 06 的两层权限同源，UI 不会和后端规则漂移。
- **查询缓存 + 推送**：引入 TanStack Query；任务列表/看板/条目状态是带缓存的查询，变更自动失效；标注绘制**乐观更新**，409（版本冲突）回滚重拉——对齐 ADR 0022 的乐观版本；工作流事件（被打回、审阅完成）走 SSE/WebSocket，无手动刷新。
- **词表管理屏** `/admin/vocab`：注册表浏览、每项目启用矩阵、候选提升队列——工单 02 注册表模型的 UI 之家（包壳方案没有这块，是 B 的实质增量）。
- **管理台三屏**：用户（建号/临时密码/禁用）、分配看板（(Clip, Task type) 行、按状态分列、指派审阅人、自动分配、已交付标记就地操作）、项目列表。Clip/媒体注册走 CLI/配置文件（低频，界面后置）。
- **工作台状态驱动**：标注员登录默认"我的任务"列表；条目内按状态出现 提交（标注中）/ 撤回（已提交）/ 打回复注横幅。审阅者打开待审条目 = 同一工作台 + 通过 / 打回+备注。词表编辑控件对标注员隐藏（收权）。
- **ClipDesk 拆解纪律**：54K 单文件拆为播放器/时间轴/编辑卡/mask 面板/词表库，按面板列渐进实现工单；**每拆一刀跑 Playwright e2e，全绿再进下一刀**；外观像素级不变（文件重构，非重设计）。
- **v1 非目标**：通知/消息系统、进度图表（看板行状态即进度）、导出管线（"已交付"为手动标记，导出工具另行立项）、审阅意见楼层（仅一条备注）、注册向导。
- bundle 影响已确认可忽略：React Router + TanStack Query 约 20–30 KB gzip。

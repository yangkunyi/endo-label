## Answer

Desk display only; `endo_label/mask/session.py` untouched and the blocking span design stays (maintainer decision 2026-09-08). While a Propagate Job runs, the rail's `data-propagate-progress` line shows an indeterminate spinner plus "Propagating… m:ss from Frame N — mask edits wait until it finishes."; the fake `frames_done/frames_total` counter is gone because the whole span streams inside the first `GET /api/jobs/{id}` poll, so no honest per-frame number exists. Elapsed seconds tick from Job start (one `setInterval` in `ClipDesk.tsx`, reset in `runPropagate` when the Job is accepted). Completion/failure toasts are unchanged and still report `frames_done`/`frames_total`.

The SAM loading state surfaces two ways: the desk polls `GET /api/health` every 5 s (SWR) and shows "Loading SAM model…" in the footer while `worker.status == "loading"`; and a Predict/Propagate failure whose message starts with "Loading" shows that label instead of the raw error. Message text is the signal because the loading failure reaches the desk as 503 (`WorkerNotReady`) or 500 (`PredictorRuntimeError` via `_require_ready`) with the same health message; load failures ("SAM 3.1 load failed: …") are not remapped. The loading toast stays error-styled because the requested action did not run. Scrub, span writes, and vocab edits are untouched; Predict/Propagate gating and 409/503 toasts behave as before.
